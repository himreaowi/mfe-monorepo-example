# Business licences (`@org/internet-business-licences`)

Remote of the **internet** zone (`access: private`). Federation name `internet_business_licences`,
dev port `3214`. Generated by `pnpm gen:remote internet business-licences`.

The internet shell mounts it at `/business-licences/*` (entry in the shell's `remotes.json`) and loads
`./App` at runtime from the URL in `mfe-manifest.json`.

## Commands

| Command                                                 | What                                                                        |
| ------------------------------------------------------- | --------------------------------------------------------------------------- |
| `pnpm exec nx dev @org/internet-business-licences`      | Standalone on http://localhost:3214 (mock host props) + the zone's mock API |
| `pnpm --filter @org/internet-business-licences dev`     | Standalone only (the demo's API calls fail without the mock API)            |
| `pnpm dev:internet` (repo root)                         | Inside the shell: http://localhost:3200/business/business-licences          |
| `pnpm --filter @org/internet-business-licences build`   | Production build in `dist/` (`mf-manifest.json`, `remoteEntry.js`)          |
| `pnpm --filter @org/internet-business-licences preview` | Serve `dist/` on port 3214 (CORS enabled)                                   |
| `lint` / `typecheck` / `test`                           | ESLint, `tsc`, Jest                                                         |

## Rules

- `src/app/apps.tsx` is the exposed module (`./App`, default export = the embedded app). Nothing
  it reaches may import global styles (`@org/design-tokens/global.scss`) or register a service
  worker: the shell owns the page. Only `src/main.tsx` (standalone) does that; `apps.test.tsx`
  checks it.
- Routes in `src/app/routes.tsx` are relative. Link between pages with `useRemotePath()` from
  `@org/mf-runtime/remote` (gives `/business-licences/details` in the shell, `/details` standalone).
- Never import another remote or a shell (`pnpm check` and ESLint module boundaries fail).
- Dependencies: see `docs/adding-dependencies.md` (catalog vs app-local).

## Data: the API pattern

`settings.apiBaseUrl` (host prop from the shell's `mfe-manifest.json`; in standalone dev the
`standaloneProps` in `src/app/apps.tsx`) is the API base URL; in development it is the zone's mock API
(`tools/mock-api`, `http://localhost:3290/api`). The demo feature shows the whole chain, copy it for real
features:

| Layer                                    | File                                                                                                                   |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| paths                                    | `src/core/constants/apiRoutes.ts`                                                                                      |
| client                                   | `useApiClient()` from `@org/mf-runtime/remote` (base URL from `settings.apiBaseUrl`, `credentials: 'include'`)         |
| requests, response validation, errors    | `src/features/demo/api/itemsApi.ts` (+ test with a fake fetch)                                                         |
| state (loading / error / data, abort)    | `src/features/demo/hooks/useItems.ts`, `useCreateItem.ts` (+ tests with the api mocked)                                |
| page (calls the hooks, passes data down) | `src/pages/OverviewPage/OverviewPage.tsx`                                                                              |
| UI (display only, props in)              | `src/features/demo/components/DemoItems/`, `AddItemForm/` (validate on submit, error summary, server 422 field errors) |

Pages fetch, components display: a feature component never calls a data hook itself, so every
API call of a page is in the page file (`docs/coding-conventions.md` "Data fetching").

## Layout

```
src/
  main.tsx            standalone entry only: global styles + <StandaloneApp />
  app/                apps (exposed ./App: createRemoteApp + standalone props), routes
  components/         ModeBadge/
  features/demo/      sample feature (host props, counter, links, items from the API + form)
    api/ hooks/ types/ utils/
    state/            only with `gen:remote --state`: feature state (reducer + Context)
    components/       one folder per component: Demo/, DemoDetails/, DemoItems/, AddItemForm/
                      (<Name>.tsx, <Name>.module.scss, <Name>.test.tsx; no index.ts)
    index.ts          public API (components and data hooks for the pages)
  layouts/            StandaloneLayout/ (own simple chrome, standalone only)
  pages/              OverviewPage, DetailsPage, NotFoundPage
  core/constants/     app, routePaths, apiRoutes
```

One folder per component, its own CSS module (never shared), a test for every component, shared
test data in `features/<feature>/__fixtures__/`: see the repo's `docs/coding-conventions.md`
("One folder per component"); `pnpm check` reports violations.
