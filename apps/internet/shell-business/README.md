# Business Portal (`@org/shell-business`)

Host app of the **internet** zone, served at base path `/business` (package.json
`mfe.basePath`). Federation name `internet_shell_business`, dev port `3202`. Generated by
`pnpm gen:shell internet business` (title from `--title`, default "<Name> shell"; layout
copied from the `side` starter, `--layout`; base path from `--base-path`).

A zone can have several shells, each under its own base path with its own layout, sign-in
config (`mfe.devManifest.auth` here, the `auth` section of each environment's manifest) and
remotes (`remotes.json`). `pnpm dev:internet` serves them all on one origin through the zone's
dev proxy: this shell is http://localhost:3200/business/.

## Commands

| Command                                     | What                                                                                                                                       |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `pnpm dev:internet` (repo root)             | Every internet shell + remote + the zone's mock API (and mock vendor) (Nx, in parallel) and the dev proxy: http://localhost:3200/business/ |
| `pnpm exec nx dev @org/shell-business`      | The shell alone on http://localhost:3202/business/ + the zone's mock API                                                                   |
| `pnpm --filter @org/shell-business dev`     | Only the shell (no mock API)                                                                                                               |
| `pnpm --filter @org/shell-business build`   | Production build in `dist/`                                                                                                                |
| `pnpm --filter @org/shell-business preview` | Serve `dist/` (needs a `dist/mfe-manifest.json`, see below)                                                                                |
| `lint` / `typecheck` / `test`               | ESLint, `tsc` (src + e2e), Jest                                                                                                            |
| `pnpm e2e:internet` (repo root)             | The zone's e2e suite (Playwright + axe), see below                                                                                         |

## How remotes get in

- `remotes.json` is the **registry**: one entry per remote (`name`, `title`, `path`,
  `federationName`, `package`, `access`, `kind`). The nav and the routes (`<path>/*` →
  `<RemoteApp>`) are built from it. `pnpm gen:remote internet <name>` adds entries.
- `mfe-manifest.dev.json` is served as `/mfe-manifest.json` by the dev server. It is
  **generated** (`pnpm dev-manifest` at the repo root; this shell's `dev` script, `pnpm e2e` and
  the generators run it too), never edited by hand: each remote of `remotes.json` points at its
  dev server (`http://localhost:<its package.json mfe.port>/mf-manifest.json`); everything else
  comes from `mfe.devManifest` in this shell's `package.json`: `auth` (`{ "mock": true }`),
  `settings.apiBaseUrl` (`/business/api`: the shell's same-origin API path on the zone's dev proxy,
  which forwards it to `API_UPSTREAM` from `.env`, by default the zone's dev-only mock API,
  `http://localhost:3290/api`, `tools/mock-api`; production nginx does the same) and
  per-remote dev `props` (`remotes.<federationName>.props`, e.g. an adapter's `vendor`).
  `pnpm check` fails when the file is out of date. The shell passes `settings` to every remote. Shell code that calls an API uses
  `useApiClient()` from `@org/mf-runtime` (same base URL, `credentials: 'include'`).
- In production the shell fetches `/mfe-manifest.json` at startup. It is **not** built in: DevOps
  writes one per environment next to `index.html` (same shape, real URLs). One build serves every
  environment.
- Remotes marked `"access": "private"` are wrapped in `<RequireAuth>` (`src/pages/RemotePage`):
  signed-out users see a sign-in prompt and the remote's code is not downloaded until they sign
  in. Every remote receives host prop `user`.

## Auth

`src/main.tsx` creates the auth client from the manifest's `auth` section
(`loadAuthClient` from `@org/auth`) and `App` wraps everything in `<AuthProvider>` (always; auth
is optional per environment):

| `auth` in `/mfe-manifest.json`               | Result                                                       |
| -------------------------------------------- | ------------------------------------------------------------ |
| `{ "mock": true }` (`mfe-manifest.dev.json`) | Dev-only mock: "Sign in" signs in as a fake user, no backend |
| `{ "sessionUrl", "loginUrl", "logoutUrl" }`  | BFF session (HttpOnly cookie). The browser never sees tokens |
| missing                                      | Sign-in disabled; private routes show "Sign-in unavailable"  |

Production builds do not contain the mock client (a `"mock": true` manifest disables sign-in
there). The BFF contract (endpoints, cookies, CSRF, CORS) is in `docs/auth-contract.md` at the
repo root. The header shows `UserMenu` (Sign in / name + Sign out).

The shell never imports a remote's code (no dependency on remote packages). The guardrails
(`pnpm check`, ESLint module boundaries) fail if it does.

## Layout: this shell owns it

`src/layouts/ShellLayout/` is this shell's own code, copied from the `side` starter
when the shell was generated. Nothing else depends on it: restyle and restructure it freely.
Changing it rebuilds and redeploys only this shell (no remote, no other shell).

| File                      | What                                                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `ShellLayout.tsx`         | structure: skip link, header (brand, `RemoteNav`, theme toggle, user menu), offline banner, `<main>` with `<Outlet />` |
| `ShellLayout.module.scss` | colours ("HEADER COLOURS" block at the top, light and dark), spacing, breakpoints                                      |
| `ShellLayout.test.tsx`    | unit tests (landmarks, skip link, Menu disclosure, measured layout)                                                    |

It is built from small `@org/ui` building blocks (shared, so every app behaves the same):
`SkipLink`, `Brand` (one line, ellipsis, full accessible name), `ThemeToggle`,
`useMenuDisclosure` (the Menu button and its panel or drawer: `aria-expanded`/`aria-controls`,
Escape returns focus, outside click, closes after a followed link and on back/forward) and
`useFitLayout` (measures whether the header row fits and switches between `wide` and
`compact`, so it collapses behind "Menu" whenever it does not fit, not at a fixed breakpoint),
plus `UserMenu` from `@org/auth`.

- **Colours**: edit the `--header-*` values at the top of `ShellLayout.module.scss` (a blue
  example is in the comment there). Keep text, muted text and accent at 4.5:1 or more on the
  header background in both themes (`a11y.spec.ts` scans the header in light and dark).
- **Nav position**: `top` = nav in the header row; `side` = sticky top bar + sidebar on the left
  from 896 px, a drawer behind "Menu" below. To switch, edit `ShellLayout.tsx` and its SCSS, or
  copy the other starter from `tools/generators/templates/shell-layouts/` at the repo root
  (`RemoteNav` takes `orientation="vertical"` for a sidebar). When to choose which:
  `docs/ui-context.md` "Navigation: top or side" at the repo root.
- **Shell-wide styles** (fonts, a page token override for the whole shell):
  `src/styles/shell.scss`, imported in `src/main.tsx` after `@org/design-tokens/global.scss`.
- **e2e contract**: the generated header tests find the layout through a few hooks the starter
  sets (`data-testid` `main-header` with `data-layout` and `data-nav-placement`,
  `header-brand`, `header-menu-button`, `header-panel`; the "Menu" button; the `<nav>` named
  "Main"); they are listed at the top of `e2e/helpers.ts`. Keep them, or adapt the helpers.

## e2e (this shell)

`e2e/` holds this shell's Playwright suite (`playwright.config.ts` → `@org/playwright-config`). It
starts `pnpm dev:internet` (or reuses it when already running), tests the shell through the
zone's dev proxy at http://localhost:3200/business/ (specs navigate to `zone.home` and `remote.path`, both below
the base path), waits for every remote in
`mfe-manifest.dev.json` and the mock API's `/health`, and runs on a desktop and a 375 px mobile
viewport. The specs read `remotes.json`, so a new remote is covered without editing them:

| Spec                 | Checks                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shell.spec.ts`      | home lists every remote, nav opens each without a reload, 404, theme persists, offline banner, header one row at 320/375/800/1024/1280 px (signed in and out; brand on one line, full name in the accessibility tree and the home `<h1>`), Menu disclosure on phones, landmarks + skip link + keyboard order; side layout (`data-nav-placement="side"`): sidebar from 896 px, drawer below, sticky top bar |
| `remotes.spec.ts`    | per remote: deep link + reload, in-remote links (after the data loaded), private guard (nothing downloaded before sign-in, mock sign-in, sign-out), external adapter: any vendor mounts content without errors and unmounts; with the mock vendor also vendor routing + theme via the shell                                                                                                                |
| `standalone.spec.ts` | per remote: its own dev server renders standalone (own chrome, theme), deep link                                                                                                                                                                                                                                                                                                                           |
| `a11y.spec.ts`       | axe WCAG 2.2 A/AA on every page above (plus the signed-in header with the Menu open), light and dark theme                                                                                                                                                                                                                                                                                                 |

`e2e/helpers.ts`: `openNav(page)` / `openHeaderMenu(page)` (open the Menu panel when the header is compact),
`resizeHeader(page, width)` (resize, then wait until the header layout settled),
`settle(page)` (network idle and no loading indicator, before link checks and axe scans),
`openRemote`, `openStandalone`, `signInWithMock`, `signOut`.

Every test also fails on a console error, an uncaught exception or a failed HTTP request (with
its URL); allow expected ones per test with `consoleErrors.allowHttp({ url, status })`. Run one
spec or project:
`pnpm --filter @org/shell-business e2e e2e/a11y.spec.ts --project=desktop`. Details:
`docs/testing.md` at the repo root.

## Layout

```
e2e/                  zone e2e suite (Playwright + axe), helpers.ts reads remotes.json
src/
  main.tsx            entry: global styles, PWA, load + validate /mfe-manifest.json, render
  styles/shell.scss   shell-wide global styles (empty by default)
  app/                App (providers + router), routes, registry typing
  components/         RemoteNav/
  features/           welcome/components/Welcome/ (home page content),
                      startup/components/StartupError/ (manifest/connection errors);
                      one folder per component (docs/coding-conventions.md)
  layouts/            ShellLayout/ (this shell's own layout: structure, colours, tests)
  pages/              HomePage, RemotePage, NotFoundPage
  core/               constants, types
```
