# Citizen Portal (`@org/shell-internet`)

Host app of the **internet** zone. Federation name `internet_shell`, dev port `3200`.
Generated by `pnpm gen:shell internet` (title from `--title`, default "<Zone> shell"; nav
placement from `--layout`, here `top`).

## Commands

| Command                                     | What                                                                                         |
| ------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `pnpm dev:internet` (repo root)             | This shell + every internet remote + the zone's mock API (and mock vendor) (Nx, in parallel) |
| `pnpm exec nx dev @org/shell-internet`      | The shell on http://localhost:3200 + the zone's mock API                                     |
| `pnpm --filter @org/shell-internet dev`     | Only the shell (no mock API)                                                                 |
| `pnpm --filter @org/shell-internet build`   | Production build in `dist/`                                                                  |
| `pnpm --filter @org/shell-internet preview` | Serve `dist/` (needs a `dist/mfe-manifest.json`, see below)                                  |
| `lint` / `typecheck` / `test`               | ESLint, `tsc` (src + e2e), Jest                                                              |
| `pnpm e2e:internet` (repo root)             | The zone's e2e suite (Playwright + axe), see below                                           |

## How remotes get in

- `remotes.json` is the **registry**: one entry per remote (`name`, `title`, `path`,
  `federationName`, `package`, `access`, `kind`). The nav and the routes (`<path>/*` →
  `<RemoteApp>`) are built from it. `pnpm gen:remote internet <name>` adds entries.
- `mfe-manifest.dev.json` is served as `/mfe-manifest.json` by the dev server. It points each
  remote at its dev server (`http://localhost:<port>/mf-manifest.json`) and
  `settings.apiBaseUrl` at the zone's dev-only mock API (`http://localhost:3290/api`, `tools/mock-api`);
  the shell passes `settings` to every remote.
- In production the shell fetches `/mfe-manifest.json` at startup. It is **not** built in: DevOps
  writes one per environment next to `index.html` (same shape, real URLs). One build serves every
  environment.
- Remotes marked `"access": "private"` are wrapped in `<RequireAuth>` (`src/pages/RemotePage`):
  signed-out users see a sign-in prompt and the remote's code is not downloaded until they sign
  in. Every remote receives host prop `user`.

## Auth

`src/bootstrap.tsx` creates the auth client from the manifest's `auth` section
(`loadAuthClient` from `@org/auth`) and `App` wraps everything in `<AuthProvider>` (always; auth
is optional per environment):

| `auth` in `/mfe-manifest.json`               | Result                                                       |
| -------------------------------------------- | ------------------------------------------------------------ |
| `{ "mock": true }` (`mfe-manifest.dev.json`) | Dev-only mock: "Sign in" signs in as a fake user, no backend |
| `{ "sessionUrl", "loginUrl", "logoutUrl" }`  | BFF session (HttpOnly cookie). The browser never sees tokens |
| missing                                      | Sign-in disabled; private routes show "Sign-in unavailable"  |

Production builds do not contain the mock client (a `"mock": true` manifest disables sign-in
there). The BFF contract (endpoints, cookies, CSRF, CORS) is in `docs/auth-contract.md` at the
repo root. The header shows `UserMenu` (Sign in / name + Sign out). The header is always one row:
when brand, nav, theme toggle and user menu do not fit (always on phones, on wider screens too
with many remotes) `MainLayout` folds them behind a "Menu" button; no shell code is needed for it.

The shell never imports a remote's code (no dependency on remote packages). The guardrails
(`pnpm check`, ESLint module boundaries) fail if it does.

## Navigation: top or side

`src/layouts/ShellLayout/ShellLayout.tsx` passes `navPlacement={NAV_PLACEMENT}` to `MainLayout`.
`'top'`: the remotes nav is in the header row. `'side'`: a sticky top bar (brand, theme toggle,
user menu) and a sidebar with the nav on the left from 896 px; narrower, a drawer behind
"Menu". To switch, change that one constant: `RemoteNav` follows (`useNavPlacement()`), the
header colours apply to the sidebar too, and the e2e suite checks whichever layout the page
shows. When to choose which: `docs/ui-context.md` "Navigation placement" at the repo root.

This shell uses **`'top'`** (the default): few areas with short names, so the pages keep the
full width.

## Header colours

The header belongs to the shell. Give it its own colours in `src/styles/shell.scss` (imported in
`src/bootstrap.tsx` after `@org/design-tokens/global.scss`): uncomment the example and set
`--header-bg`, `--header-text`, `--header-text-muted`, `--header-border` and `--header-accent`
for `:root, [data-theme='light']` and for `[data-theme='dark']`. Unset, the header uses the page
tokens. With `navPlacement` `'side'` the same tokens colour the sidebar and the drawer. Keep text, muted text and accent at 4.5:1 or more on `--header-bg` in both themes
(`a11y.spec.ts` scans the header in light and dark). Remotes never set these tokens
(`pnpm check`).

Do not style the header through `MainLayout`'s class names (`.header`, …): they are CSS Modules
classes, renamed to a hash at build time (different per build, per app and in dev vs
production), so such selectors silently stop matching. Details: `docs/ui-context.md` "Header
colours per shell" at the repo root.

This shell keeps the default header (white in light, the dark surface in dark); nothing is set.

## e2e (the whole internet zone)

`e2e/` holds the zone's Playwright suite (`playwright.config.ts` → `@org/playwright-config`). It
starts `pnpm dev:internet` (or reuses it when already running), waits for every remote in
`mfe-manifest.dev.json` and the mock API's `/health`, and runs on a desktop and a 375 px mobile
viewport. The specs read `remotes.json`, so a new remote is covered without editing them:

| Spec                 | Checks                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shell.spec.ts`      | home lists every remote, nav opens each without a reload, 404, theme persists, offline banner, header one row at 320/375/800/1024/1280 px (signed in and out; brand on one line, full name in the accessibility tree and the home `<h1>`), Menu disclosure on phones, landmarks + skip link + keyboard order; side placement: sidebar from 896 px, drawer below, sticky top bar |
| `remotes.spec.ts`    | per remote: deep link + reload, in-remote links (after the data loaded), private guard (nothing downloaded before sign-in, mock sign-in, sign-out), external adapter: any vendor mounts content without errors and unmounts; with the mock vendor also vendor routing + theme via the shell                                                                                     |
| `standalone.spec.ts` | per remote: its own dev server renders standalone (own chrome, theme), deep link                                                                                                                                                                                                                                                                                                |
| `a11y.spec.ts`       | axe WCAG 2.2 A/AA on every page above (plus the signed-in header with the Menu open), light and dark theme                                                                                                                                                                                                                                                                      |

`e2e/helpers.ts`: `openNav(page)` / `openHeaderMenu(page)` (open the Menu panel when the header is compact),
`resizeHeader(page, width)` (resize, then wait until the header layout settled),
`settle(page)` (network idle and no loading indicator, before link checks and axe scans),
`openRemote`, `openStandalone`, `signInWithMock`, `signOut`.

Every test also fails on a console error, an uncaught exception or a failed HTTP request (with
its URL); allow expected ones per test with `consoleErrors.allowHttp({ url, status })`. Run one
spec or project:
`pnpm --filter @org/shell-internet e2e e2e/a11y.spec.ts --project=desktop`. Details:
`docs/testing.md` at the repo root.

### Feature specs (this example)

Besides the generated specs: `services.spec.ts` (search, detail, topic filter), `announcements.spec.ts` (list, detail, back), `my-profile.spec.ts` (sign in → profile → save choices with the CSRF token → sign out), `payments.spec.ts` (validation, `payment:completed` reaches the host, vendor receipt via the shell URL, theme and user via `update()`), and `a11y-features.spec.ts` (axe on detail pages and forms with errors, light + dark).
They use the generated helpers (`openRemote`, `settle`, `openHeaderMenu`, `signOut`).
The generated external-adapter test runs against the example vendor (`tools/example-vendors`);
the mock-vendor-only test skips because `props.vendor` is not the mock vendor, and `payments.spec.ts`
covers vendor routing and the theme instead.

## Layout

```
e2e/                  zone e2e suite (Playwright + axe), helpers.ts reads remotes.json
src/
  main.tsx            import('./bootstrap') (shared singletons are negotiated first)
  bootstrap.tsx       global styles, PWA, load + validate /mfe-manifest.json, render
  styles/shell.scss   shell-owned global styles: header colours (--header-*) per theme
  app/                App (providers + router), routes, registry typing
  components/         RemoteNav
  features/           welcome/components/Welcome/ (home page content),
                      startup/components/StartupError/ (manifest/connection errors);
                      one folder per component (docs/coding-conventions.md)
  layouts/            ShellLayout (MainLayout from @org/ui + nav)
  pages/              HomePage, RemotePage, NotFoundPage
  core/               constants, types
  services/           http client (base URL from manifest settings)
```
