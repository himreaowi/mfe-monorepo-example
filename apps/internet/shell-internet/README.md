# Citizen Portal (`@org/shell-internet`)

Host app of the **internet** zone. Federation name `internet_shell`, dev port `3200`.
Generated by `pnpm gen:shell internet`.

## Commands

| Command                                     | What                                                        |
| ------------------------------------------- | ----------------------------------------------------------- |
| `pnpm dev:internet` (repo root)             | This shell + every internet remote (Nx, in parallel)        |
| `pnpm --filter @org/shell-internet dev`     | Only the shell, on http://localhost:3200                    |
| `pnpm --filter @org/shell-internet build`   | Production build in `dist/`                                 |
| `pnpm --filter @org/shell-internet preview` | Serve `dist/` (needs a `dist/mfe-manifest.json`, see below) |
| `lint` / `typecheck` / `test`               | ESLint, `tsc` (src + e2e), Jest                             |
| `pnpm e2e:internet` (repo root)             | The zone's e2e suite (Playwright + axe), see below          |

## How remotes get in

- `remotes.json` is the **registry**: one entry per remote (`name`, `title`, `path`,
  `federationName`, `package`, `access`, `kind`). The nav and the routes (`<path>/*` →
  `<RemoteApp>`) are built from it. `pnpm gen:remote internet <name>` adds entries.
- `mfe-manifest.dev.json` is served as `/mfe-manifest.json` by the dev server. It points each
  remote at its dev server (`http://localhost:<port>/mf-manifest.json`).
- In production the shell fetches `/mfe-manifest.json` at startup. It is **not** built in: DevOps
  writes one per environment next to `index.html` (same shape, real URLs). One build serves every
  environment.
- Remotes marked `"access": "private"` are wrapped in `<RequireAuth>` (`src/pages/RemotePage`):
  signed-out users see a sign-in prompt and the remote's code is not downloaded until they sign
  in. Every remote receives host prop `user`.

## Auth

`src/bootstrap.tsx` creates the auth client from the manifest's `auth` section
(`loadAuthClient` from `@org/auth`) and `App` wraps everything in `<AuthProvider>` (always; auth
is optional per environment):

| `auth` in `/mfe-manifest.json`               | Result                                                       |
| -------------------------------------------- | ------------------------------------------------------------ |
| `{ "mock": true }` (`mfe-manifest.dev.json`) | Dev-only mock: "Sign in" signs in as a fake user, no backend |
| `{ "sessionUrl", "loginUrl", "logoutUrl" }`  | BFF session (HttpOnly cookie). The browser never sees tokens |
| missing                                      | Sign-in disabled; private routes show "Sign-in unavailable"  |

Production builds do not contain the mock client (a `"mock": true` manifest disables sign-in
there). The BFF contract (endpoints, cookies, CSRF, CORS) is in `docs/auth-contract.md` at the
repo root. The header shows `UserMenu` (Sign in / name + Sign out).

The shell never imports a remote's code (no dependency on remote packages). The guardrails
(`pnpm check`, ESLint module boundaries) fail if it does.

## e2e (the whole internet zone)

`e2e/` holds the zone's Playwright suite (`playwright.config.ts` → `@org/playwright-config`). It
starts `pnpm dev:internet` (or reuses it when already running), waits for every remote in
`mfe-manifest.dev.json`, and runs on a desktop and a 375 px mobile viewport. The specs read
`remotes.json`, so a new remote is covered without editing them:

| Spec                 | Checks                                                                                                                                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shell.spec.ts`      | home lists every remote, nav opens each without a reload, 404, theme persists, offline banner                                                                                                              |
| `remotes.spec.ts`    | per remote: deep link + reload, in-remote links, private guard (nothing downloaded before sign-in, mock sign-in, sign-out), external adapter mounts the mock vendor (vendor routing + theme via the shell) |
| `standalone.spec.ts` | per remote: its own dev server renders standalone (own chrome, theme), deep link                                                                                                                           |
| `a11y.spec.ts`       | axe WCAG 2.2 A/AA on every page above, light and dark theme                                                                                                                                                |

Every test also fails on a console error or an uncaught exception. Run one spec or project:
`pnpm --filter @org/shell-internet e2e e2e/a11y.spec.ts --project=desktop`. Details:
`docs/testing.md` at the repo root.

### Feature specs (this example)

Besides the generated specs: `services.spec.ts` (search, detail, topic filter), `announcements.spec.ts` (list, detail, back), `my-profile.spec.ts` (sign in → profile → save choices with the CSRF token → sign out), `payments.spec.ts` (validation, `payment:completed` reaches the host, vendor receipt via the shell URL, theme and user via `update()`), and `a11y-features.spec.ts` (axe on detail pages, forms with
errors and the open Menu, light + dark). `helpers.ts` adds `openNav()` (the nav is behind a
"Menu" button below 40rem) and `settle()` (wait for the features' API calls before asserting or
scanning). `playwright.config.ts` also waits for the mock API (`settings.apiBaseUrl` + `/health`).

## Layout

```
e2e/                  zone e2e suite (Playwright + axe), helpers.ts reads remotes.json
src/
  main.tsx            import('./bootstrap') (shared singletons are negotiated first)
  bootstrap.tsx       global styles, PWA, load + validate /mfe-manifest.json, render
  app/                App (providers + router), routes, registry typing
  components/         RemoteNav
  features/           welcome (home page content), startup (manifest/connection errors)
  layouts/            ShellLayout (MainLayout from @org/ui + nav)
  pages/              HomePage, RemotePage, NotFoundPage
  core/               constants, types
  services/           http client (base URL from manifest settings)
```
