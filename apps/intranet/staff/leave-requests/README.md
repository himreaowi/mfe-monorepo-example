# Leave Requests (`@org/intranet-leave-requests`)

Remote of the **intranet** zone (`access: public`). Federation name `intranet_leave_requests`,
dev port `3111`. Generated by `pnpm gen:remote intranet leave-requests`.

The intranet shell mounts it at `/leave-requests/*` (entry in the shell's `remotes.json`) and loads
`./App` at runtime from the URL in `mfe-manifest.json`.

## In this example

Leave balance per type, the user's requests and a request form (`/leave-requests/new`) with
validation, an error summary that takes focus, field errors linked with `aria-describedby`, and
the API's 422 field errors shown the same way. The optional "Covering colleague" field is the
`StaffPicker` of the zone library `@org/intranet-directory` (search staff with the keyboard); the
choice is sent as `coverId` and the overview shows "Covered by ..." for requests that name one. Working days are counted with **date-fns**, a
tier-3 (app-local) dependency of this remote only (`pnpm --filter @org/intranet-leave-requests
add date-fns`, normal semver range, no catalog entry, no exception).

## Commands

| Command                                              | What                                                               |
| ---------------------------------------------------- | ------------------------------------------------------------------ |
| `pnpm --filter @org/intranet-leave-requests dev`     | Standalone on http://localhost:3111 (mock host props)              |
| `pnpm dev:intranet` (repo root)                      | Inside the shell: http://localhost:3100/leave-requests             |
| `pnpm --filter @org/intranet-leave-requests build`   | Production build in `dist/` (`mf-manifest.json`, `remoteEntry.js`) |
| `pnpm --filter @org/intranet-leave-requests preview` | Serve `dist/` on port 3111 (CORS enabled)                          |
| `lint` / `typecheck` / `test`                        | ESLint, `tsc`, Jest                                                |

## Rules

- `src/app/apps.tsx` is the exposed module (`./App`, default export = the embedded app; it also
  holds the standalone mock host props). Nothing it reaches may import global styles
  (`@org/design-tokens/global.scss`) or register a service worker: the shell owns the page. Only
  `src/main.tsx` (standalone) does that; `apps.test.tsx` checks it.
- Pages fetch, components display: a page calls the feature's data hooks (exported from the
  feature's `index.ts`; the client is `useApiClient()` from `@org/mf-runtime/remote`) and passes
  data and callbacks down (`docs/coding-conventions.md` "Data fetching").
- Routes in `src/app/routes.tsx` are relative. Link between pages with `useRemotePath()` from
  `@org/mf-runtime/remote` (gives `/leave-requests/details` in the shell, `/details` standalone).
- Never import another remote or a shell (`pnpm check` and ESLint module boundaries fail).
- Dependencies: see `docs/adding-dependencies.md` (catalog vs app-local).

## Layout

```
src/
  main.tsx            standalone entry only: global styles + <StandaloneApp />
  app/                apps (exposed ./App: createRemoteApp + standalone props), routes
  features/leave/     api/, hooks/, types/, utils/, __fixtures__/, components/ (one folder per
                      component: LeaveOverview/, LeaveBalanceCards/, LeaveRequestList/,
                      LeaveRequestForm/ with its private Field.tsx)
  layouts/            StandaloneLayout/ (own simple chrome, standalone only)
  pages/              OverviewPage, NewLeavePage, NotFoundPage (they call the data hooks)
  core/constants/     app, routePaths, apiRoutes
```
