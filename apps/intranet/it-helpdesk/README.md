# It Helpdesk (`@org/intranet-it-helpdesk`)

**External module adapter** of the **intranet** zone (`access: public`, tag `kind:external`).
Federation name `intranet_it_helpdesk`, dev port `3103`. Generated by
`pnpm gen:remote intranet it-helpdesk --external`.

This remote is a thin React adapter: it renders `<ExternalModule>` from
`@org/mf-runtime/external`, which loads a vendor-built bundle and drives the **mount contract**
(`mount(el, props) → { update?, unmount }`, see `docs/external-modules.md` at the repo root).
The vendor can use any framework (or another React major); nothing is shared with the shell.

## Where the vendor bundle comes from

From this remote's `props.vendor` in the shell's `mfe-manifest.json`, **per environment** (never
in the build):

```json
"intranet_it_helpdesk": {
  "entry": "https://cdn.example.sg/it-helpdesk/mf-manifest.json",
  "props": {
    "vendor": {
      "url": "https://vendor.example/it-helpdesk/1.4.2/mount.js",
      "format": "esm",
      "integrity": "sha384-…",
      "timeoutMs": 15000,
      "config": { "merchantId": "…" }
    }
  }
}
```

`format`: `esm` | `web-component` (+ `tagName`) | `script` (+ `global`) | `mf` (+ `remoteName`).
`config` is passed to the vendor as `props.config`.

In development the shell's `mfe-manifest.dev.json` points at the **mock vendor**
(`tools/mock-vendor`, http://localhost:3999/mount.js), and `src/features/external/vendorConfig.ts`
falls back to it when no config is set (standalone mode). Production builds contain neither.

## Commands

| Command                                         | What                                                                    |
| ----------------------------------------------- | ----------------------------------------------------------------------- |
| `pnpm dev:intranet` (repo root)                 | Shell + all intranet remotes + the mock vendor (Nx task dependency)     |
| `pnpm exec nx dev @org/intranet-it-helpdesk`    | This adapter standalone on http://localhost:3103 + the mock vendor      |
| `pnpm --filter @org/intranet-it-helpdesk dev`   | This adapter only (start `pnpm --filter @org/mock-vendor dev` yourself) |
| `pnpm --filter @org/intranet-it-helpdesk build` | Production build in `dist/`                                             |
| `lint` / `typecheck` / `test`                   | ESLint, `tsc`, Jest                                                     |

## What the adapter passes to the vendor

| Prop                 | From                                                                   |
| -------------------- | ---------------------------------------------------------------------- |
| `basePath`, `path`   | shell mount (`/it-helpdesk`) and the sub-path below it (vendor routes) |
| `theme`              | shell theme (`useTheme()`), updates via `update()`                     |
| `user`               | shell host prop `user`, reduced to `{ id, name, roles }`               |
| `config`             | `props.vendor.config` from the manifest                                |
| `onNavigate`         | shell router (relative = below `/it-helpdesk`, `/x` = shell route)     |
| `onEvent`, `onError` | demo "Events from the module" panel: replace with real handling        |

Loading/mount errors, timeouts, an incompatible `contractVersion` or a fatal `onError` show
`RemoteFallback` with "Try again"; the shell keeps working. Leaving the route calls the vendor's
`unmount()`.
